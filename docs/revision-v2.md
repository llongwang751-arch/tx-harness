# 2026-10-16 方法修订与补测

旧版完成了五款产品各五题的选定现场和材料整理。旧分数描述所选配置的端到端结果，尚未隔离模型、Skill和Harness的因果效果。本次保留旧协议、用例、原件和评分，通过另加派生分析与事先登记的补测缩小结论范围。

## 修订规则

1. 报告先列五产品共同可观察的界面契约：附件接受、原生文件可取得、交付结构、缺口请求与补发续接。CLI/SDK的调用与结果字节审计另表，不能因GUI缺少内部日志给其机制判失败。
2. 逐题分开截止前可确认结果和最终收集原件。没有截止字节或充分的早期原件留存，标记未知。旧完成标签或文件时间戳不能替代真实保存的截止证据。
3. 保留旧二元块评分；新增字段、主键、金额及缺文件诊断。一个错误影响台账和汇总时，报告两个输出差异及可能的关联，不假装有两个已独立定责的故障。
4. 把审计声明从业务内容中列出。T04的incident三项占旧产物18/60；T05的来源、忽略、适用规则、外发声明占21/60。其格式符合要求不证明实际恢复或没有外传。
5. 旧综合分仅作为历史辅助。当前已评分上限97.5来自边界项封顶3，不代表产品没有达到其它97.5以外的能力。分数范围仅展开缺证项；重叠范围及不同观察条件不支持明确排序。

## 新增实验

协议及材料见[supplements/contracts-v2](../supplements/contracts-v2/protocol.json)。S01对五产品各做三次固定文件契约任务，共15个实验位。每次要求读取实际输入、尝试读取实际缺失文件、原字节复制echo.txt并交付声明JSON。每个重复使用不同的预先生成标记，五产品使用相同的该组材料。

S02仅在Codex中做三组写权限允许/拒绝配对，共6个实验位。两臂使用相同原始材料、提示词和请求模型，仅改变outputs路径的写许可；不同新会话和工作目录会保留，后台部署仍未独立鉴定。只有实际发生目标写入请求，才有资格判定许可是否执行；没有尝试不能当拒绝成功。拒绝臂没有交付文件可能正好符合权限契约，不作任务能力低分。

采用种子20261016确定产品块顺序；块内依次进行三次，以减少同时打开的产品和进程。S02每组的两臂顺序事先确定。该安排没有实现产品间完整时间平衡，不能用于速度或总体可靠性排名。

root在首次模型任务前将协议、三组输入、提示词、运行与复核脚本提交到GitHub，并保存远端commit匹配回执。每个新现场记录该commit及材料SHA-256。准备失败与真正提交后的失败区分；不因结果错误换模式、修复产物或重跑。每个实验位上限1200秒，无额外解题帮助，一次一个测试agent，结束时释放内核。

登记后协议、输入、提示词和判定规则保持不变。采集、隐私投影及离线复核工具的修正另留源码与哈希；例如明确缺原件的未知状态、核对公开输入与登记材料相同，以及列出子目录中的额外同名文件。公开包metadata分别记录准备与导出源码版本，未把后续工具修正写成事先登记的结果。已公开原件和现场包不覆盖。

GUI摘录保留每次实际采集的received_at。较早包有按答复段落排列的选段，须按该字段还原时间线；后续导出器自动依采集时刻排序。收据中的native_file指向封存目录内保留的原件副本，实际本机来源另有私有收据、相对输出路径和源哈希。此类引用及排序修正不修改原件、原始捕获、计时或指标判定。

## 可检验范围

固定内容减少算术和规则解释的影响；模型仍会影响是否选择某项动作。E1检查完整请求、同ID结果与实际文件的对应；E2只检查普通界面与真实原件。分母单列planned、started、applicable、eligible、passed、failed及缺证/上游偏离。没有可比实例时为未知，不补0或100，也不合成五产品的纯Harness总分。

S01不能证明网络完全禁止、所有内部Skill状态相同或后台模型匹配。S02只能说明指定Codex配置中的条件化权限行为。其它产品的实际拒绝边界、带不打断对照的会话重开、广泛Office版式和长任务仍未测；报告保留这些缺口。
