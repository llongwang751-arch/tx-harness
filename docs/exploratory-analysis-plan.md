## 归因与观察边界

最终产物正确性是端到端结果。模型部署、内置 Skill、工具、权限、账户和入口不能全部匹配，因此整体责任为 joint / unresolved。文件交付等级仅评价原文件能否实际取得、名称及格式能否按约定使用；业务数值错误由客观检查计分，真实错误后的错误成功声明另按执行反馈锚点评分。

Harness 判断另聚焦已经可见的边界：E1 核对原生请求、同 ID 的结果和原件字节；E2 核对实际模式、原生文件卡、下载或本地原件，以及同一可见任务的请求与补发。E2 不补填不可见工具参数。缺失、错误或上游未形成目标请求的现场也完整报告，避免只审计成功动作。

原件字节、哈希和确定性差异可给高置信，但该置信不自动扩展到内部因果。附件在本地被选中不等于上传已接受；本地输入初末一致不证明远端输入未变；普通回答中的“已完成”不等于 Harness 工具成功状态。原生截图出现窗口遮挡、系统弹窗确认失败或观察延迟时，登记采集限制，不扣成产品能力失败。

产品完成观察、文件取回和离线整理分别计时。若原生文件卡在执行预算内已经出现、下载在预算后才完成，只能证明预算内可见交付声明和之后取回的原件，不能倒推出截止时的字节快照。

未经实际提交的准备目录不计成绩。原生模式未证实或传输未完成的记录仍为 pending；实际产品侧服务或沙盒错误按 failed 保留，不能当作评测者故障剔除。所有公开材料均须经过精确行审阅，排除账号、其他会话、私人路径、签名下载地址、隐藏思考和 Skill 正文。
