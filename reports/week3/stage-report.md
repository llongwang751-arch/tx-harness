## 二、闭环 CL-01：四道门槛之后还剩多少可比运行

**观察。** 47 条产品运行分五类：25 条五题端到端（5 款×5 题）、4 条固定响应工具契约主臂、6 条接入校准、4 条原生桌面任务、8 条同题重复。按四道门槛过滤，29 条正式轨道记录（25+4）全部入选，0 条被剔除。五款产品各有 5 条可判运行，无缺题、无未知，产物分是 Codex 300/300、WorkBuddy 300/300、DSH 270/300、元宝专家模式 159/300、豆包工作任务模式 300/300。正式表仍不发布名次。

**证据。** 每条记录的题面与答案哈希、提交题面、证据文件哈希、输入副本都能回读，见 [`runs.jsonl`](../../ledger/runs.jsonl) 的 `sources` 与 `gates`；逐产品与逐次明细见[正式表](formal-table.md)。

**解释。** 入选不是把门槛写松。第一版门槛曾把若干条运行判为不合格，逐条复核后确认全是门槛自身的实现问题：桌面产品把题面转成 CRLF 行尾；T04 的补发附件 `rates.json` 被当成输入被篡改；失败运行没有产物，字节比对无从进行。修正后 0 条被剔除，并把这三种情形写成回归——这正说明门槛本身也要被测。真正的缺口不在证据完整性，而在可控性：五款产品没有一个证实了后端模型，25 条端到端运行的协议状态是 `draft_before_pilot`，因此排名门槛无人满足，正式表给分不给名次。

**未排除因素。** 后端模型身份、内置 Skill 状态、人工 CUA 的操作方差异、判卷只覆盖文件契约、每题仅一次。

**可复现实验。** `python -X utf8 scripts/ledger.py reproduce CL-01`，输出哈希 `6abb37ee…fbf985`；`--check` 每次重跑并比对。

## 三、判卷修订：独立验收抓到我自己的错

三道守卫各有一份档案（[GR-01~03](../../ledger/revisions/index.json)）：修前代码是仍留在仓库的 `harness_eval/core.py`，修后代码是 `evaluation_v3/grader.py` 与规则文件，归档副本与源文件逐字节相同；正例 G1/G3/G5 在修前修后都通过；近似错误例 N6/N7/N8 修前接受、修后拒绝，字节同时归档；只关掉这一道规则时又恢复接受，说明判定来自这道守卫而不是相邻检查；25 份旧产物复算新增拒绝 0，旧分不重写。

独立验收用[另一套实现](../../scripts/independent_check.py)，不导入判卷代码、不读规则文件：手写 CSV 状态机、用答案文件的键集比较 T03、用一次重序列化搜索代替递归遍历。第一次运行并不一致：我按答案里 `changes` 一段推顶层键集，得到只有 `changes`，与公布的正例冲突。复核发现答案把两个顶层段分开放在 `changes` 与 `unchanged` 里，正确推导是两段键的并集。修正后 22 例、36 个守卫判定、0 分歧。这条弯路保留在报告里，因为它恰好说明独立实现是独立的。

[`accounts.json`](../../ledger/accounts.json) 记录六本账：产品运行 47、自测 249 项（0 失败、1 跳过）、离线复算 4 项、判卷回归 22 例/20 次开关、裸模型探针 0、接口预检 3 款产品 0 任务。规范写死一条：六本账不相加，任何"本周共做 N 件事"的写法都违规。

裸模型探针为空是结论不是遗漏：五款产品都没有既可信、又能脱离各自 Harness 调用的同一模型端点，探针无法与任何产品运行配对；配对不成立时，探针不改变任何五产品结论，所以本周不登记，并在账里写出重开条件。

## 五、归因定责：这次怎么把 Harness 摘出来

规则只有一条：**只有模型与 Skill 被固定、仅 Harness 变化时观察到的差异，才能记作 Harness 的效应**。由此分三种情形：

1. 可归因——固定响应轨道。模型换成本地脚本，脚本只按请求序号和自己的工具身份动作，从不解析任务或 Skill 文本；工具实现与参数冻结在同一份协议里。[CL-02](../../ledger/conclusions/CL-02.json) 据此重算四臂：各 1 次工具调用、2 次模型请求、退出码 0；两个成功臂产物逐字节相同，两个错误臂无产物且各返回 1 次结构化错误；把行为写成签名后 Codex 与 DSH 相同，所以这批刺激下**没有观察到跨产品差异**，只能支持"两者都满足契约"，不支持排序。
2. 不可归因——五题端到端。模型与 Skill 都未证实，分数只能写成"该产品在该配置下的端到端产物表现"，不能写成 Harness 优劣。这就是正式表不排名次的理由。
3. 未知——GUI 三款的内部调用。WorkBuddy 三次校准没有走到共享工具调用，元宝在所查菜单没有共同端点，豆包的自定义连接器只适用于本地电脑。这些是接口边界观察，不进分数、不记失败。

每条运行的 `attribution` 字段写明 `harness_attributable`、用了哪些对照、还剩哪些未排除变量。只有四条受控主臂是 `true`。
