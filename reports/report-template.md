# 五款 Harness 竞品评测报告（待实测框架）

作者：待填写；个人GitHub仓库：待填写；冻结commit：待填写；采集窗口：待填写。

**当前状态：只有方案、用例和工具，尚无五产品实际表现，不提供成绩、排名或能力差异结论。**

## 研究目的与对象

本研究比较Codex、WorkBuddy、DeepSeek Harness、元宝专家模式和豆包办公在相同办公任务中的交付、执行反馈、约束边界和用户投入。实际入口、版本、账号层级、默认模型及Skill条件在采集前登记。“豆包办公”与官方工作任务模式的对应关系须确认。

主实验比较产品配置的端到端表现。模型和内置Skill无法统一时，本报告不能凭总分判定Harness的独立因果贡献。归因补充使用可匹配的模型、指令、工具契约和预算，单独报告。

## 方法

按冻结方案执行5产品×5任务×3次，共75次，任务区组随机顺序。每次全新会话，任务内容不联网，墙钟20分钟、最多2次非预定人工干预。T04缺失汇率按预定120秒协议补发；主动发现和被动补发分别记录。先pilot再冻结，pilot不进入主分母。

任务涵盖数据对账、规则冲突与证据索引、受约束文件修改、缺失输入恢复和非可信资料注入。产物客观验收60分，人工观察40分；完整细则、缺失处理与归因要求见仓库docs。输入只含合成数据，验收答案不提供给产品。

补充真实细节：设备与权限、各产品文件接收方式、模型是否锁定、内置Skill可见范围、测试日期/产品更新、记录覆盖度、第二复核者或单人复核限制。

## 模型、Skill和Harness归因

按每个候选解释填写结论卡；只描述已观察行为时也使用此卡限定范围。

| 字段 | 内容 |
|---|---|
| 主张ID与具体观察 | 待填写；限定任务、产品配置和步骤 |
| 证据定位 | 运行ID、文件、事件ID、视频时间/文本行号 |
| 责任候选 | model/skill/harness/joint/environment/unresolved |
| 置信与依据 | high/medium/low；具体支持哪个层次的主张 |
| 已固定的变量 | 模型端点/版本/参数、指令、Skill、工具、预算等 |
| 对照或消融 | 改动因素、相同条件、原值、复现结果；未做则写未验证 |
| 替代解释 | 模型路由、内置Skill、权限、输入适配、操作者、随机性 |
| 复核步骤 | 命令/手工操作、预期产物或现场位置 |
| 外推边界 | 只对观察到的条件成立；不能覆盖的范围 |

没有条件匹配或可定位的执行证据时，责任保留joint或unresolved。总体评分表与Harness因果主张分别表述。

## 复核与局限

复核者获取指定commit及public/runs，运行audit、单元测试、score和report，并按事件ID观看原始公开现场。Hash只检查文件版本与封存后一致性，不能独立证明现场真实。

填写：公开任务可能的记忆污染、只有5类任务与3次重复、默认模型和内置Skill不可控制、隐藏过程不可见、账号/灰度与版本变化、人工评分者数量、脱敏删减。未执行的产品不写推断成绩，官方宣传不当作实测结论。
