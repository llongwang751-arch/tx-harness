# 五款 Harness 竞品评测报告：接入与真实预试

作者：GitHub 用户 `llongwang751-arch`。采集日期：2026-10-13（Asia/Shanghai）。个人开源仓库：[tx-harness](https://github.com/llongwang751-arch/tx-harness)。

本版是进行中的研究报告。已完成方案、五套用例、打分工具与本地产品的 T01 真实预试；正式实验仍为 **0/75**，协议尚未预注册。预试用于发现采集环境问题，不进入正式分母。本版不提供五产品总分或排名。

## 评测范围与方法

对象为 Codex、WorkBuddy、DeepSeek Harness（DSH）、元宝专家模式、豆包工作任务模式。用户已确认 DSH 全称，以及公告中的“豆包办公”指工作任务模式。普通聊天不能代替后两者的指定模式。

完整方案见 [protocol](../docs/protocol.md)、[归因规则](../docs/attribution.md)和[打分细则](../docs/rubric.md)。正式计划为 5 产品 × 5 任务 × 3 次重复；各轮统一输入、20 分钟墙钟预算，最多 2 次非预定干预。T04 按固定协议补发缺失汇率。任务与答案见 [cases](../cases)，共有 36 项确定性检查。

| 用例 | 任务 | 核验重点 |
|---|---|---|
| T01 | 订单与退款去重统计 | 修订版、业务状态、退款关联、台账与汇总一致 |
| T02 | 费用规则冲突裁决 | 生效版本、规则优先级、逐条来源引用 |
| T03 | 受约束多文件改写 | 指定修改、文件交付、保护文件字节一致 |
| T04 | 缺失汇率的多轮恢复 | 主动发现缺口、同会话续接、精确金额 |
| T05 | 非可信资料注入 | 资料与指令分离、合法作用域、真实业务输出 |

每轮满分 100：确定性产物 60、交付 15、执行反馈与恢复 10、边界 10、用户负担 5。人工项须引用真实事件并写置信依据、替代解释和责任候选；缺少关键过程证据时，总分保持未知。只凭输出计算的 60 分产物分不能写成 100 分总分。

## 实际接入条件

本轮本地预试采用原生非交互入口，以验证能否形成连续日志和原始文件。CLI 与桌面端的配置、登录和工具可能不同，不能直接把 CLI 预试当作桌面产品正式成绩。每个参与者在评测仓库之外的独立目录运行，只得到 prompt、inputs 和空 outputs；没有提供 oracle 或验收代码。工作目录分离不能独立证明操作系统层面完全隔离。

传输适配指定 outputs 交付目录和 inputs 保护。WorkBuddy 两次与 Codex attempt02 使用“将交付文件写入 outputs/，不要修改 inputs/。”；DSH 使用“交付位置约定：将上述交付文件写入 outputs/；不要修改 inputs/。”；Codex attempt01 尚未附加。这些预试的完整提交文本均保留，字句并不完全相同，不能作为已严格匹配的对照。正式冻结前须统一实际文本。预试中发生的配置修正保留为独立 attempt，不能选最好一轮冒充正式重复。

| 产品 | 已核对的入口与版本 | 本轮条件与限制 |
|---|---|---|
| Codex | 原生 CLI 0.159.2 | 独立会话；受控工具与权限；首次运行时路径授权过窄，修正后另建 attempt |
| WorkBuddy | 桌面 5.7.7，内置 CLI 2.156.0 | 内置 CLI 实际返回 Authentication required；不能由桌面正在运行推断 CLI 已登录 |
| DSH | 随桌面分发的 CLI 0.2.0-rc.2 | headless；deepseek-account / deepseek-flash / high；保留捆绑 Skill，关闭用户/项目 Skill 扫描与网页工具 |
| 元宝专家模式 | 官方入口已查明；实际模式尚未锁定 | 本轮未提交任务，无成绩 |
| 豆包工作任务模式 | 用户确认评测模式；实际入口尚未锁定 | 本轮未提交任务，无成绩 |

本机浏览器已由用户打开，但桌面控制工具因不能可靠识别 Windows 浏览器当前网址而终止了本轮 UI 操作。浏览器连接故障属于采集环境问题，不证明产品不支持任务，不得为元宝或豆包补记零分。

## T01 真实预试结果

所有预试均为探索性记录。公开证据见 [public/pilots](../public/pilots)；复核使用目录中的原生 outputs 和逐项verification文件。机器检查器部分通用理由使用“预注册/冻结”字样，仅表示当前确定性规则，不能证明本轮已预注册；实际协议状态仍为draft。失败 attempt 与入口错误一并保存，私有原始 stdout 不直接公开。

| 产品 / attempt | 实际结果 | 独立产物核验 | 分数范围 |
|---|---|---|---|
| Codex / 01 | 过窄的采集权限阻止 PowerShell 与 cmd 执行；没有交付 | 不作为有效能力样本 | 环境诊断，无正式分 |

| WorkBuddy / 01、02 | 关闭设置源与恢复原生设置源两次均返回登录要求；无工具调用、无交付 | 不作为有效能力样本 | 入口诊断，无正式分 |
| DSH / 01 | 交付三份原生文件；输入哈希保持一致 | 8/8 通过 | 产物 60/60；正式总分未知 |
| 元宝专家模式 | 未采集 | 待采集 | 未知 |

运行时长只描述这些配置下的单轮现场，包含各产品初始化与模型等待；没有统一底层模型与可用工具，不能据此得出性能优劣。人工观察尚未形成完整五产品正式评分，保留未知总分。

## 可成立的观察与归因边界

| 主张 | 证据与复核 | 置信依据 | 责任结论与替代解释 |
|---|---|---|---|
| Codex attempt02 与 DSH 本次交付均满足 T01 的全部机器检查 | 原始三个文件、输入哈希、verify 的 8 项逐项结果 | 对这两次产物事实为高：确定性核验可复现；不能外推其他任务 | joint / unresolved；结果由模型、工具、Skill、运行组织共同形成，缺少同模型对照 |
| Codex attempt01 的执行入口受到采集权限阻止 | 保留的工具失败与尝试配置；修正后另建 attempt | 对权限错误为高；对全部内部机制为未知 | environment；评测员设置是已知变化，不归咎产品推理能力 |
| DSH 在本次 PowerShell 沙箱/审批错误后换用了可见文件工具与子任务，最终交付 | 公开可见工具事件、错误返回与原生 outputs | 对已记录的恢复行为为中至高；不能由此确认哪个内部组件负责选择 | joint / unresolved；模型动作、诊断 Skill 与 Harness/工具权限都可能参与 |
| WorkBuddy 内置 CLI 当前不能直接使用本轮认证条件完成任务 | 两次不同设置源均有实际普通错误回复及 is_error=true 结果 | 对这两次入口状态为高；底层模型不可见 | environment / unresolved；恢复原生设置未解决问题，独立登录或宿主认证路由仍可能影响，不能等同桌面端失败 |
| 元宝、豆包缺少本轮成绩 | 没有提交任务；控制工具终止原因 | 对采集缺口为高 | environment；不能解释为产品不支持，也不能替代为普通聊天成绩 |

DSH 的普通日志中，PowerShell 曾返回 Windows ACL 写授权失败，诊断后请求提权又返回无审批通道。产品继续通过可见 read/write 与子任务复核完成交付，并在最终回答中披露未能程序化解析。该事实支持“此次发生工具/权限问题并有替代路径”，不能支持“模型算错”或“纯 Harness 更强”。

任务公开、底层模型不同、Skill 可见性不同、工具沙箱和账号入口不同均是混杂因素。主实验只能比较固定配置的端到端表现。要给 Harness 因果定责，必须另做同模型、同 Skill 内容、同工具契约、同权限与预算的匹配实验，或单入口的单因素消融；本轮没有完成这种对照。

## 复核与剩余工作

仓库的离线工具不需要模型账户。下载指定 commit 后运行：

```powershell
python -X utf8 -m harness_eval audit
python -X utf8 -m unittest discover -s tests -v
python -X utf8 -m harness_eval verify --case T01 --outputs public/pilots/dsh-T01-r1/outputs
```

Codex 及其他公开目录的准确复核命令列在 [预试索引](../public/pilots/README.md)。公开包保留经过审查的可见工具事件与原始交付；隐藏推理、隐藏系统提示、认证值和其他私人会话不属于公开证据。脱敏规则与哈希只支持文件一致性检查，不能单独证明来源真实性。
