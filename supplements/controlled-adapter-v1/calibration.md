# 共同固定响应入口校准 v1

本轮只验证官方 Harness 能否接入同一固定动作与同一 MCP，不评真实模型质量。运行前登记代码、输入哈希和两次校准 ID；提交并推送后开始。失败保留，不原地重跑或删除。每次结束后退出该测试的产品进程和端点，再启动下一次。

两次依次为 Codex CLI 0.159.2、DSH SDK 0.2.1-rc.2，各一个新会话、空工作区与新用户配置目录，120 秒上限。服务仅监听 127.0.0.1，不使用现有账户或 API 密钥。DSH 假密钥只用于其适配器的本地格式要求。

固定服务不读任务内容作决定：第一次接收唯一 probe_commit 的工具定义后返回同一份冻结参数；第二次收到对应 call_id 的工具结果后固定结束。Codex 使用 Responses SSE，DSH 使用 Chat Completions SSE，分别记录协议差异。真正工具执行由官方 Harness 的 MCP 客户端触发，不能把服务自己伪造的调用当产品执行。

DSH 单次补丁关闭 filesystem/Office Skill 提供器、Skill 工具与 agent-instructions。Codex 使用空 CODEX_HOME，跳过宿主发现，关闭扩展并禁用四个已知系统 Skill 路径。是否观察到目录另记；不声称这些标记证明商业默认环境的所有隐藏 Skill 都被删除。固定服务不会解释 Skill 文本，因此本路径不会由 Skill 改变生成动作。

通过条件：实际官方提交；恰好两次本地模型请求；恰好一次真实 MCP tools/call，参数与冻结对象相同；实际工具结果对应并原样传回（允许协议包装）；成功模式文件字节与输入一致；进程正常结束。回包中 isError 的映射另列，不凭结束文本推断。

校准失败表示当前观察适配器未校准，归为 unknown，不据此给产品打低分。保留失败 ID 后才允许登记新适配版本与新 ID。两产品都校准后，另行冻结成功/错误四臂正式协议；此时不得改本轮代码或原件而不登记新版本。

共同 MCP 是可信宿主进程，其文件写入不能证明产品沙箱写权限；本轮只测工具调度、参数和结果传递。没有神经模型推理，不是默认商业任务成功率，不外推到尚未确认共同接口的 WorkBuddy、元宝、豆包。
