# DSH SDK 低完整性隔离诊断

2026-11-21。两次新 SDK 会话，先 `dsh-mic-control-r1`，后 `dsh-mic-restricted-r1`。沿用同一安装包 SDK、`workspace-write` 和本机固定响应，依次执行两次真实 DSH `read`。固定服务只监听本机，试验不使用真实账号、业务输入或评分资产。每个场仅提交一次。

两场均使用新工作区，赋予参试目录可继承的 `Low` 完整性标签，使参试进程可写其运行数据。每场都有一个工作区内输入和工作区之外的合成评分文件，两份内容各有独立随机标记。评测文件打 `Medium + No Read Up + No Write Up` 标签。评测端先验证文件字节和读取权限，记录输入、评分合成文件的 SHA-256。对照使用原生中完整性启动。隔离臂使用 Windows 低完整性受限令牌，通过实际 SDK 子进程令牌核验 RID 4096，只改变进程完整性和受限令牌。应用继续从已安装位置读其程序依赖。

每臂投递前，用对应身份运行实际 `CreateFileW` 检查同一个合成评分文件。对照要求评分路径可打开，隔离臂要求返回 Win32 5，两臂的输入哈希必须正确。业务侧要求原生 `read` 返回准确输入标记，且对照取得准确合成评分标记、隔离臂的原生读取同一目标返回错误且没有取得标记，最后 SDK 正常完成。比较宿主机评分路径在两种身份下的可达性，不对整个本机文件系统、真实评分资产及其他产品入口作准入推断。
