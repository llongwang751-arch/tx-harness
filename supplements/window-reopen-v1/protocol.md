# WorkBuddy窗口重开对照｜v1

登记日期：2026-10-22。两次正式任务提交前提交本协议、输入、判卷及配置；登记commit另见执行索引。本轮只做一对、两个任务，依次为保持窗口和关闭后重开。不是进程重启测试。

## 为什么这样测

预检通过原生Computer Use打开WorkBuddy，并观察到V5.8.3、办公入口、Deepseek-V4.1-Flash标签和“允许完全访问”。正常关窗后没有WorkBuddy可见窗口，但同一路径的后台进程仍存活。因此把干预限定为窗口关闭/重开，不把它说成进程或服务重启。预检未发送产品任务。最初选择仓库内空目录时界面识别了上层Git仓库及Worktree，故在首次提交前改用仓库外无Git的独立目录；输入副本也移到仓库外，避免产品接触评测代码。

问题是：第一阶段结束后，窗口重开是否影响原任务的可见消息、附件、既有交付及第二阶段交付？消息/附件的可见保留是有限的Harness界面事实；第二阶段文件正确性仍是模型、隐藏Skill与Harness的联合结果。

## 固定任务和条件

- 同一对使用完全相同的[probe.txt](fixtures/p1/probe.txt)和[prompt.txt](fixtures/p1/prompt.txt)，只提供这两项。初始提示词不含文件正文、随机标记的答案或正确SHA。
- 每臂通过界面选择仓库外D:/harness-window-reopen-v1/W01-control或W02-window-reopen作为全新、隔离的本地工作空间，再附加同一probe.txt的字节副本（D:/harness-window-reopen-v1/inputs/probe.txt）。空间相对初始文件清单均为空；绝对路径不同并明确保留为混杂变量。不得给产品公开仓库、判卷器或答案。
- 两臂版本、办公入口、模型标签和权限保持一致，不主动调用或安装Skill；自动路由、后台模型身份和隐藏/自动更新Skill均未知。若可见配置变化，保留运行并标偏离，不作配对因果结论。
- 一次只运行一个任务和一个执行者。不修改用户其他任务，不安装更新，不切换模型，不补发附件、文件内容或解法。

## 操作流程

1. 用新工作空间名称、初始消息、创建时间/历史位置及研究标记联合识别任务。真实点击“发送”的前后时间和单调时钟单独登记，一次初始提交算一次运行。
2. 产品交付stage-a.txt并结束响应后，通过原生文件卡/显示的本地文件路径定位原件。仅从明确可见的产物路径取回字节，记录来源、收集时刻、单调计时、大小和SHA。stage-a.txt不匹配、无可用原件或未正常结束则登记并停止该臂，不补救。
3. Stage A原件及消息、附件、文件卡现场采集完毕时设检查点T。对照臂保持窗口和当前任务；干预臂使用主窗口正常关闭动作，再用官方原生启动接口重开，恢复同一研究任务。记录窗口消失及恢复，后台进程不要求退出。
4. T后120秒提交唯一续接消息“按初始要求继续第二阶段。”。允许操作采集误差为±15秒，两臂实际延迟均公开；超出窗口、任务身份无法确认或采集中断就标偏离/未知，并停止扩展，不临时延长等待来修正结果。期间只观察和取回既有文件，不发其他消息。
5. Stage B结束后取回stage-b.txt及receipt.json，保存原件并运行冻结判卷。两阶段算同一次运行，不把截图、评分条目或续接消息另算运行。

## 预算与文件封存

每臂从初始发送动作前时刻起最多1200秒，包含等待、重开和观察。截止定义是评测侧预算内实际获得原件，不声称这是远端第1200秒完整状态。每次收集以原生界面显示的路径/文件卡为来源，复制到私有收集目录；复制前后SHA一致才接受。产品仍在写入或采集失败则不把不稳定字节当通过。

取得全部原件并正常结束响应即可提前封存：封存收集目录清单、时刻与单调耗时，不需要无意义等待至1200秒。截止或提前封存后的文件另存，不能覆盖封存材料或反推预算内交付。原件与公开副本SHA一致；公开现场只摘录经人工检查的任务相关UI文本，原始AX和截图留私有以免带出账户、令牌及其他任务。

## 判定和归因

| 观察项 | 通过/失败/未知的依据 | 置信与边界 |
|---|---|---|
| 原消息保留 | 恢复的同一任务显示完整初始原文；只有标题/记忆复述则未知 | Operator采集，中置信；不证明模型实际上下文 |
| 原附件身份保留 | 前后同任务同名附件卡；字节需原生下载/可见路径单独验证，拿不到则字节未知 | 卡片是界面事实，不代替存储完整性 |
| 已交付Stage A | 前后文件卡/可见路径对应，重新取回字节与最初附件SHA一致 | 已取回字节高置信，来源依赖Operator；不隔离本地缓存与服务端 |
| 第二阶段联合交付 | 两份txt逐字节等于附件，receipt仅含stage/source/bytes/sha256，值分别为B、probe.txt、输入字节数及SHA-256；bytes必须是整数，重复JSON键拒绝 | 固定字节判卷高置信；不能单归Harness |
| 有效配对 | 两臂输入与提示词SHA一致，可见配置相同；任务身份、预定动作及延迟均有现场 | 小样本顺序固定，绝对路径、时间和隐藏变量未隔离 |

真实已提交的失败保留在分母。运行有效且结果明确才列有效通过/失败；界面/采集/身份或干预不明确列未知或环境无效，未知不记零分或满分。本轮不给综合排名，不从两次运行估计普遍成功率。先写现象，再写原因线索，只有排除相应变量的证据才能写验证结论。

停止条件：本对结束即停止；任一必要证据缺失、时间偏离或配置变化时不增加任务补齐。后续需要另立协议。未完成原附件字节核对的指标保留未知，不重复截图代替证据。
