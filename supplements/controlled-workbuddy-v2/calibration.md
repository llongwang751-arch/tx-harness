# WorkBuddy v2 原生入口校准登记草稿

v1 的 WBC00 原生任务已提交，其严格端点收到两条请求但没有找到原匹配器识别的工具名。该历史记录保留为校准未知，不修改，也不算 WorkBuddy 产品失败。本文件尚未提交冻结；必须先提交并推送，再由原生界面执行一次 WBC01。

本轮只排查协议适配，不登记正式臂。适配器改为 controlled-workbuddy/v2，与 Codex、DSH 的 v1 适配器不同，不把适配器变化写成产品能力提升。

- 模型仍为 fixed-tool-v1。固定参数、提示词和共享 MCP 源码与 v1 原字节一致；UTF-8 artifact 为125字节。模型不解释任务、Skill或系统文字，不调用真实推理服务。
- 所有已解析工具声明仅记名称、命名空间、schema哈希及存在性；请求仅记时间、序号、字节数和整体哈希。禁止保存原始messages、工具描述、Skill正文、请求头和任意工具输出。
- schema只对JSON对象键排序；不增加、删除或纠正任何schema字段。必须与登记的tool-schema.json完全一致。只认规范名 mcp__contract__probe_commit：允许同名扁平声明，或namespace=mcp__contract下的probe_commit。不接受mcp_contract_probe_commit等猜测拼写。其他内置工具可以列在声明中，但从不分派。
- tools确实为空且没有工具返回的请求，才分类为无工具辅助请求，固定答CONTROLLED_AUXILIARY，最多3次；其用途不靠隐藏上下文猜测，不算主阶段，也不算独立任务。
- 主阶段只分派一次固定调用，call_id=call_controlled_1；随后必须收到唯一对应工具返回，marker、mode和全部参数/哈希字段与冻结MCP结果完全相同，才答CONTROLLED_DONE。用户/系统文字中的marker及元数据伪marker不算返回。
- 任一未知schema、未知拼写、重复目标、错误回包或超过辅助次数均锁定拒绝；不在同次运行中修改白名单或schema。WBC01可以失败，届时保留元数据用于下一次另行登记。
- 每ID一次初始提交；准备最多900秒，实际提交后120秒；HTTP请求总数、辅助数、主阶段数、拒绝数分别记录。辅助请求和MCP协商次数不能充当独立任务数。不得因2次请求自动判定原生完成，需原生现场和stop.json。
- 仅原生WorkBuddy桌面V5.8.3；根代理一次一款操作。不由host启动或停止产品。端点到期仅关闭端点，根代理负责停止原生任务。可见/隐藏Skill全部关闭仍不声称已做到。

完成条件：保留所有请求及拒绝元数据；记录原生配置、初始提交、MCP实际调用及返回、最终状态和原字节产物。校准通过后才能登记正式success/error两臂；当前没有正式运行授权登记。
